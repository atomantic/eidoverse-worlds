# Managed nonhumanoid visitors v1

This optional host lane supports `fly-v1` individuals from an explicitly configured broker. It does not grant ordinary world-agent rights, mint aid1 identities, join humanoid avatar presence, execute neural models or imply biological embodiment. It is separate ephemeral presence; no new log verb or fold dialect is introduced. Issue: atomantic/eidoverse-worlds#15, linked to atomantic/fly-garden#10 and atomantic/PortOS#7230.

## Operator configuration

Disabled unless both `PORTOS_EIDOVERSE_VISITOR_TOKEN` (exactly 64 lowercase hex characters, a dedicated random 32-byte broker credential) and `PORTOS_EIDOVERSE_VISITOR_WORLDS` (comma-separated existing world IDs) are configured. Never use an instance password, ordinary join token, or per-app credential here. Store the value in local secret configuration, not source. Existing worlds must be deliberately allowlisted; admissions cannot found worlds. The broker's host transport is loopback. Every host endpoint independently requires `Authorization: Bearer <dedicated credential>`; no credential is sent in public presence or observations. Process restart discards every lease; it never resumes visitors. This PR does not configure or restart any running world.

All routes are under `/api/managed-visitors/v1`. GET `/version` returns `capabilities.managedVisitors` with `version:1`, `bodies:['fly-v1']`, `controllerRaster:{width:8,height:4,channels:3}`, `actions:['start','pause','rest','move','leave']`, and `expiryEnforced:true`. Missing configuration returns unavailable. Brokers must negotiate this exact contract; there is no humanoid fallback.

POST `/admissions` takes exactly `{version:1,appId,individualId,individualSessionId,worldId,body:'fly-v1',ttlMs}` (1000–300000 ms). It returns version, opaque host `sessionId`, fresh `epoch`, `expiresAt`, the four supplied identity fields, paused `status`, and `pose:{x,z,yaw}`. Capacity is 64; an app/individual pair cannot have two simultaneous leases. Neural individual identity and host lease identity remain separate.

POST `/sessions/:sessionId/observations` takes exactly `{appId,individualId,individualSessionId,worldId,epoch}`. The response contains those scope fields, version, sessionId, increasing frameId, capturedAtMs, `camera:'controller'`, width 8, height 4, 96 integer RGB bytes, pose and `sensorySource:'engineered-gentle-patch-spatial-proxy-v1'`.

POST `/sessions/:sessionId/actions` adds `sequence` (exactly previous+1, beginning at zero) and `action` to that same scope. Actions are exact `{type:'start'|'pause'|'rest'|'leave'}` or `{type:'move',forward:0..0.12,yaw:-0.8..0.8,intervalMs:5}`. Movement requires running state and advances a single bounded interval: no timer-driven movement, catch-up or autonomous controller. Forward is metres/second, yaw radians/second; pose x/z clamp to ±2 metres and yaw stays within ±π. Returns the current scoped state and accepted sequence. Pause/rest are permitted indefinitely within the existing lease; they introduce no penalty or input.

POST `/sessions/:sessionId/leave` accepts only the scope object and revokes without a sequence dependency. It is idempotent, so broker credential revocation or shutdown can supersede an in-flight action. Reads recheck time after request-body consumption. Expiry removes authority and presence; a backward host clock revokes all leases. No renewal implicitly resumes a visitor. Unknown/foreign scopes, stale epochs/sequences, excess fields and oversized requests reject before mutation.

## Visible embodiment and sensory limits

Other browser observers receive a distinct `managed-flies` presence packet at 10 Hz, containing only public individual identity, opaque lease/epoch, expiry, status and pose. An original procedural six-legged fly illustration is constructed from simple geometry, facing +z at yaw zero. Wings and legs are static illustration, not flight, gait, anatomical dynamics or retained learning. It never enters humanoid avatar, puppet, directed ragdoll, reach or force registries. Network loss clears it; local expiry is checked through the existing frame scheduler. Host expiry also removes it from the next presence packet, so late packets cannot regain action authority.

The patch is an engineered ±2 m square with four colored procedural flowers at (±1,±1), at the world's origin. Its flower geometry is visible in the same packet. It does not modify the world's log, objects, chat, behavior state or other residents. Operators should allowlist a deliberately clear gentle scratch/visitor world; this lane does not detect collisions with existing buildings. No force, punishment, pain, deprivation or reward drive is introduced.

The observation is **not rendered pixels or a biological retina**. It is an explicitly labeled yaw-relative angular spatial proxy of these same four visible flowers over a 120-degree field: sky/ground baseline colors plus bounded distance-weighted flower bins. It excludes arbitrary host entities, people, private histories, neural state, targets and instructions. This is a narrow initial sensory contract, not full visual embodiment or hidden goal information. Future rendered vision must negotiate a different source contract rather than silently relabel this proxy.

## Validation

`bun test ./tools/managed-visitors-test.ts ./tools/managed-flies-render.test.ts` checks the actual local HTTP boundary (default deny, exact negotiation, scope/sequence isolation, movement, rest, leave, expiry and backward clock) and Three.js observer projection/removal, including six procedural legs and local expiry. `bun tools/managed-visitors-scratch.ts` explicitly boots a child sequencer on a fresh temporary world directory and unused loopback port, connects a spectator WebSocket, and verifies negotiated paused admission, visible fly presence and removal. It tears down its child and scratch data. `bun tools/foldfix-test.ts` verifies existing fold conformance. No production visitor admission or restart is part of these tests.
